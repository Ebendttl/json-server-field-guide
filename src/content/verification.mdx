Every example and behavioral claim in this guide was produced by running a real `json-server@1.0.0-beta.15` server on Node.js 22, issuing HTTP requests, and recording the responses. The recordings are stored in [`src/mdx/fg/fixtures.json`](https://github.com/Ebendttl/json-server-field-guide/blob/main/src/mdx/fg/fixtures.json) and can be replayed to verify the guide stays accurate.

## Why verify

JSON Server 1.x is a beta. Its query-parameter behavior differs from the widely documented 0.x releases, and several parameters that worked before now return empty arrays. Rather than guess at behavior, every claim in this guide traces to a specific fixture ID.

## How the recordings were made

1. A script starts a fresh `json-server` instance with a known dataset.
2. It issues a sequence of HTTP requests (GET, POST, PATCH, PUT, DELETE).
3. It records each response's status code and body.
4. It snapshots `db.json` after each scenario to confirm writes persisted.

Each scenario runs against a clean server. State carries across steps within a scenario but not between scenarios.

## Datasets

Two datasets seed the test server:

| Dataset | Collections | Records |
| --- | --- | --- |
| `quickstart` | `posts` (3), `authors` (2), `profile` (object) | 5 records + 1 singleton |
| `tasks` | `projects` (2), `tasks` (5) | 7 records |

## Scenarios and fixture counts

| Scenario | Dataset | Steps | What it covers |
| --- | --- | --- | --- |
| `quickstart-reads` | `quickstart` | 14 | GET collections, single resources, filters, sort, pagination, embed, 404 |
| `quickstart-write` | `quickstart` | 10 | POST, PATCH, PUT, DELETE, profile PATCH, missing-id errors |
| `tasks-filter-sort` | `tasks` | 35 | Equality, operators (`:gte`, `:ne`, `:lt`, `:lte`, `:gt`, `:eq`, `:in`, `:contains`, `:startsWith`, `:endsWith`), repeated params, multi-key sort, FK quirks, case sensitivity |
| `tasks-paginate-embed` | `tasks` | 21 | `_page` + `_per_page`, `_limit`/`_start`/`_end` (return `[]`), `_embed` on single and collection, edge cases |
| `tasks-write` | `tasks` | 11 | POST with/without custom id, PATCH, PUT, DELETE, cascade check, FK filter after delete |

**Total: 91 recorded requests across 5 scenarios.**

## Running the fixtures yourself

You can re-record the fixtures with the script in this repository:

```bash
node scripts/fg-record-fixtures.mjs
```

The script starts json-server, replays every scenario, and compares the recorded responses to [`src/mdx/fg/fixtures.json`](https://github.com/Ebendttl/json-server-field-guide/blob/main/src/mdx/fg/fixtures.json). Any mismatch means a claim in the guide may need updating.
